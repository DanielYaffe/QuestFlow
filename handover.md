# Character Save & Display — Handover

## The problem
Characters generated by the quest wizard were not appearing in the project Characters view or the QuestBuilder NPC picker.

## Why
`generateQuestline` saved characters only as embedded subdocs inside `questline.characters[]`.
The project Characters page and QuestBuilder CharacterPicker both query the standalone `Character` collection (`CharacterModel`) — a separate Mongoose model. Embedded questline characters are invisible to both.

## Fix (backend/src/controllers/questGenerationController.ts)
Before creating the questline, call `CharacterModel.insertMany()` for each AI-generated character.
- `character.role` (`'npc' | 'monster'`) maps directly to `CharacterModel.kind`
- `character.background` maps to `CharacterModel.lore`
- Build `charIdMap` (`"char-1"` → `CharacterModel._id`) from the inserted docs
- Set `questline.characterIds[]` to the new `CharacterModel._id`s
- Remap node `npcIds[]` / `monsterIds[]` from Gemini temp IDs to real `CharacterModel._id`s
- Embedded `questline.characters[]` is kept as-is for QuestBuilder backward compat

## How display works
- **Characters page** (`GET /characters?projectId=`): queries `CharacterModel` filtered by `projectId`
- **CharacterPicker in QuestBuilder** (`NodeEditSidebar`): calls `listCharacters({ projectId })` — same query
- **Orphan flag**: a character is non-orphan if its `_id` appears in `questline.characterIds[]` OR any node `npcIds[]`/`monsterIds[]`. The fix populates both.

## Caveat
Only questlines generated after the fix will have standalone `Character` docs. Old questlines won't backfill automatically.
